# Развёртывание Movie Catalog

Проект устроен так, чтобы исходный код и вся история изменений всегда находились в GitHub, а опубликованный сайт работал независимо от ChatGPT.

## Что используется

- GitHub — постоянное хранение кода и история версий.
- Cloudflare Worker — сайт и серверный API.
- Cloudflare D1 — небольшая SQL-база для оценок, статусов, избранного, дат и заметок.
- Общий семейный ключ — защита операций редактирования без регистрации пользователей. Просмотр каталога остаётся публичным.

На предполагаемой личной нагрузке всё помещается в бесплатные лимиты Cloudflare.

## Первичная настройка

1. Зарегистрировать бесплатный аккаунт Cloudflare.
2. На компьютере установить Node.js 22 или новее и клонировать репозиторий.
3. В папке проекта выполнить `npm ci`.
4. Выполнить `npx wrangler login` и подтвердить вход в Cloudflare.
5. Создать базу командой `npx wrangler d1 create movie-catalog-db`.
6. Идентификатор созданной базы уже указан в поле `database_id` файла `wrangler.jsonc`.
7. Создать таблицы и перенести исходную коллекцию командой `npm run db:migrate:remote`.
8. Задать длинный общий ключ командой `npx wrangler secret put ACCESS_KEY`.
9. Опубликовать сайт командой `npm run deploy`.

После первой публикации Cloudflare выдаст бесплатный адрес в зоне `workers.dev`. Затем репозиторий можно подключить в разделе Workers Builds, чтобы каждое изменение основной ветки GitHub автоматически разворачивалось на сайте.

Посетителям не требуется ключ для просмотра фильмов, описаний, оценок и статусов. Сайт запрашивает семейный ключ только при попытке изменить оценку, статус, избранное, дату просмотра или заметку, а также перед выгрузкой резервной копии.

## Красивый адрес

Бесплатный адрес Cloudflare можно использовать постоянно. Для адреса вида `movies.example.com` нужен уже зарегистрированный собственный домен. Подключение домена к Worker бесплатно, но сам домен обычно оплачивается раз в год.

## Резервное копирование

На сайте есть кнопка выгрузки всей коллекции в JSON. Её стоит использовать после больших изменений. Схема базы также хранится в GitHub в папке `migrations`.
